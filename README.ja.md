# 学習台帳 · Study Ledger

[English](README.md) · [简体中文](README.zh-Hans.md) · [繁體中文](README.zh-Hant.md) · **日本語** · [Français](README.fr.md) · [Deutsch](README.de.md)

勉強の時間が実際どこへ消えたのかを把握するためのカレンダーです。時間割の上に学習時間を
確保でき、GitHub 風の年間ヒートマップと、日・週・月・年・学期ごとの時間消費レポートが
付いています。

動かし方は二通り。デスクトップガジェットとメニューバー表示を備えた **ネイティブの
macOS アプリ** として、あるいはビルド作業がまったく要らないただのウェブページとして。
インターフェイスは 8 言語、配色は 25 種、そして文字体系ごとの書体プランを用意しています。

---

## 動かす

### macOS アプリ

```sh
./macos/build.sh --run
```

ユニバーサルバイナリの `Study Ledger.app` を `macos/build/` にビルドして開きます。
サイズは約 900 KB、パッケージマネージャも Xcode プロジェクトも要りません。必要なのは
Xcode かコマンドラインツールに付属する Swift ツールチェーンだけです。`/Applications`
にドラッグすればそのまま使えます。

```sh
./macos/build.sh            # ビルドのみ
./macos/build.sh --test     # ビルドしてヘッドレスの自己テストを実行
```

アプリはアドホック署名されており、手元で動かすにはこれで十分です。誰かに渡すなら、
`macos/build.sh` の `codesign` の行を Developer ID の証明書に差し替えて公証してください。

データは `~/Library/Application Support/Study Ledger/ledger.json` にあります。バックアップ
も同期も直接編集もできる、ただのファイルです。アプリメニューに
**データファイルをFinderで表示** があります。

### ブラウザで

`index.html` をダブルクリックするか、フォルダごと配信します。

```sh
python3 -m http.server 8000
# そのあと http://localhost:8000 を開く
```

ローカルサーバーのほうが安全です。ブラウザは `file://` で開いたページの `localStorage`
をファイル単位で区切るため、配信しておけばディレクトリを移動しても記録は一か所に
留まります。

ブラウザではすべてがキー `study-ledger-v1` の下に保存されます。どちらの動かし方でも
アカウントは不要で、データが端末の外に出ることもありません。**設定 → JSON をエクスポート**
でバックアップを書き出し、**JSON をインポート** で復元できるので、アプリとブラウザの
あいだを行き来できます。

## データの構造

三つの階層があり、カレンダーはそのすべての入力方法です。

```
授業                                  ← カテゴリ：仕事の種類
  ├ 発展最適化                        ← 項目：実際の科目・プロジェクト・書籍
  │   講義 · ノート作成 · ⋯           ← 活動：何をしたか
  └ 数値解析
研究プロジェクト
  ├ 医用画像セグメンテーション
  └ 機械学習による市場予測
読書 · スキルと語学 · その他
```

- **カテゴリ** —— 仕事の種類。*授業*、*研究プロジェクト*、*読書*、*スキルと語学*、
  *その他* が最初から入っています。**カテゴリ** ビューの最上位に並ぶのはカテゴリだけで、
  クリックするとその中の項目が開きます。
- **項目** —— 実際に時間を使った対象。科目、プロジェクト、書籍など。項目はカテゴリの
  *中* にあり、決して横に並ぶことはありません。そしてカレンダーの各ブロックの見出しに
  なります。「発展最適化」のほうが「講義」より一目で多くを語るからです。項目はただ一つの
  カテゴリに属し、それを持ち歩きます。エディタで項目を選べば、カテゴリはそれで決まります。
- **活動** —— 時間の使い方。活動は *カテゴリ* に属するので、授業の下のどの科目も同じ
  語彙を共有します。講義、ノート作成、課題 / 演習、オンライン講座、教科書読解、実験 /
  実習、演習 / オフィスアワー、復習、試験対策、グループ課題——それを項目ごとに繰り返す
  必要はありません。
- **記録** —— カレンダー上の一つのブロック。カテゴリ一つ、項目一つ、活動一つ。その長さ
  *こそが* 消費した時間なので、アプリのあらゆる合計はブロックの足し算にすぎません。

三つとも **カテゴリ** で編集できます。その場で改名、色替え、追加、削除。エディタで
**+ 新しい項目…** や **カスタム…** を選ぶと、その名前がカテゴリのリストに加わり、次回は
ひとクリックで選べます。改名は記録済みの時間ごと移りますし、項目を削除するとその下の
時間も消えます（消す前にそう伝えます）。項目のないカテゴリには項目リストがそもそも
表示されません。穴埋めのための架空の項目はつくりません。

### 記録をつける

エディタは **まず項目を尋ねます**。手持ちの項目をすべて、カテゴリごとにまとめて並べます。
一つ選べばカテゴリが埋まってロックされるので、あとは活動を選ぶだけです。ロックは意図して
開くもので——南京錠をクリックします——そのうえでカテゴリを変えると、その項目は
これまでの記録ごと引っ越します。新しい項目のときはカテゴリが開いたままです。どこかに収めなければ
ならないからです。

記録は「日付 + 深夜0時からの開始・終了の分数」で保存され、UTC のタイムスタンプでは
ありません。だから時計が変わっても学習時間が別の日にずれることはありません。深夜0時を
またぐ時間帯は、00:00 で二つの記録に分けて保存されます。

## 各ビュー

**カレンダー** —— 日・週・月。日グリッドでは、空いているところをドラッグして時間帯を
確保し、クリックだけなら既定の 1 時間になります。ブロックをドラッグすれば移動でき
（横方向に日をまたぐことも可）、下端をドラッグすれば長さが変わり、クリックすれば編集
できます。表示する時間帯は設定に従いますが、実際の記録を収めるために必ず外へ広がるので、
見えなくなるものはありません。

**ヒートマップ** —— 一年の各日に一マス。配色の主色を五段階にした階調で、連続日数、
カテゴリ別の絞り込み、月別合計、曜日ごとの平均が付きます。最も濃い段階に達する一日の
合計時間は設定項目であって、データからの当て推量ではありません。

**統計** —— 見出しの数値タイル、日/週/月ごとの時間（区切りの粒度は範囲に追随）、続いて
**カテゴリ別**、**項目別**、**活動別** の時間と、三階層の表。進行中の期間は経過した日数
で平均・比較されるので、月初が「−99%」と表示されることはありません。

**カテゴリ** —— 上記の階層構造。カテゴリ・項目・活動それぞれの累計時間つき。

**配色** —— 25 種類。ホバーでアプリ全体をプレビューし、クリックで確定します。

## デスクトップガジェット

枠のないパネルで、今日の目標に対する進み具合、今週、今日の時間が実際どこへ入ったか、
そして直近 10 週間の形を表示します。**⌘G**、**表示** メニュー、またはメニューバーの
項目で切り替えられます。

二つの高さのどちらかに置けます。角の矢印か **表示** メニューで切り替えます。

- **デスクトップに固定** —— デスクトップアイコンと同じ階層、通常のウィンドウすべての
  背面に。古典的なガジェットです。画面を片づけたときそこにあり、作業中は決して邪魔を
  しません。少し淡くなって、風景の一部として読めるようになります。
- **最前面に表示** —— すべての上に。数字を見ていたいときのために。

どこへでもドラッグできます。置いた場所を覚え、Space をまたいで付いてきます。一定の範囲で
リサイズも可能。現在の配色と書体プランをまとい、メインウィンドウで何かが保存された瞬間に
更新されます。

**メニューバーの項目** は小さな本の記号の隣に今日の合計を表示します。アプリ自身の言語と
時間表記で——`2h 30m`、`2時間30分`、`2 Std. 30 Min.`。そのメニューからウィンドウを
開いたり、新しい記録を始めたり、ガジェットを切り替えたりできます。メインウィンドウを
閉じても、ガジェットとメニューバーは動き続けます。

## 言語

English · 简体中文 · 繁體中文 · 日本語 · Español · Deutsch · Français · Latina

**設定 → 表示言語** で選びます。初回起動時はブラウザ自身の設定が一致すればそれを、
なければ英語を使います。

言語を変えても変わるのはインターフェイスだけです。カテゴリ・項目・活動の名前はあなたの
データなので書き換えられることはありません。ただし *プリセット* は台帳が最初に動いた
ときの言語で書き込まれるため、日本語で始めれば Lecture や Homework ではなく「講義」
「課題」が入ります。**プリセットを復元** は、いまの言語のプリセットを既存の内容に
足します。

日付、曜日と月の名前、時刻の書式（英語は 12 時間制、それ以外は 24 時間制）、期間の見出し、
時間の長さ——すべて言語に従います。中国語なら `7月2日` と `2小时15分`、ドイツ語なら
`2. Juli` と `2 Std. 15 Min.`。月と曜日の名前は `Intl` から取っています。`Intl` が持って
いないラテン語には、`js/i18n.js` に手書きの表があります。

言語を追加するには、`LOCALES` に一項目、`S` に他と並べて文字列表を一つ、`FORMATS` に
時間書式を一つ——いずれも [js/i18n.js](js/i18n.js) の中です。足りないキーは生のキー名を
出さずに英語へフォールバックします。

## 書体

言語に必要なのは言葉の翻訳だけではありません。そこで **設定 → 書体** では、文字体系ごとに
独自の書体プランを用意しています。どのプランにも実物の見本が付き、どの伝統に由来するかを
記しています。選択は *言語ごとに* 記憶されるので、日本語は明朝、英語は Garamond という
組み合わせも可能です。

| 文字体系 | プラン |
|---|---|
| ラテン | **Ledger**（Fraunces / Spectral——現在の Tufte 寄りの既定）· **Didone**（Playfair Display / Lora、Bodoni と Didot に倣う）· **Renaissance**（EB Garamond、Claude Garamont の 1540 年代のローマン体に倣う）· **Grotesque**（Bricolage Grotesque / Work Sans、Akzidenz の系譜） |
| 简体中文 / 繁體中文 | **宋体**（Noto Serif SC/TC——宋代の刻本の伝統）· **楷体**（LXGW 文楷 / システムの楷書）· **黑体**（Noto Sans SC/TC）· **书法**（Ma Shan Zheng の見出しに宋体の本文） |
| 日本語 | **明朝体**（Shippori Mincho）· **ゴシック体**（Zen Kaku Gothic New）· **丸ゴシック体**（Zen Maru Gothic）· **筆書体**（Yuji Syuku の見出しに明朝の本文） |

どのプランもラテン書体と CJK 書体を意図して組み合わせており、フォントスタックの順序に
よってラテン文字は必ずラテン書体から出ます。「Advanced Optimisation」と「高等最適化」が
同じ行に並んでも、声の調子は一つのままです。読み込まれるのはプランが実際に使う書体だけ
で、選び直しても書き換わるのは `<link>` 一つです。

プランを足すには、[js/fonts.js](js/fonts.js) の該当する配列に一項目を加え、その
`families`（Google Fonts のクエリ断片）と `display` / `body` / `mono` のスタックを
書きます。

## 配色

Thomas Shang の Tufte 風書籍テンプレートの 24 配色に、元のウォーム既定色を加えたもので、
[26-Xi-quizbank](https://github.com/Hatsuyuki017/26-Xi-quizbank) から移植しました。

配色の切り替えは `<html>` に `data-theme` 属性を一つ設定するだけです。各配色が宣言するのは
七つの生のトークンのみ。

```css
[data-theme="kyoto"] {
  --p-bg:  #EAE2D4;   /* 紙 */
  --p-ink: #222842;   /* 文字 */
  --p-a … --p-e;      /* カテゴリの五色 */
}
```

ほかの色——各種の面、罫線、ヒートマップの階調、予定の塗り——はすべて、`css/app.css` の
中でその七つから `color-mix()` によって導かれます。ほかの場所に決め打ちの色は一つもない
ので、配色が中途半端に当たることはありえません。

配色を変えたり足したりするには、`tools/gen_palettes.py` の `RAW` 表を編集して実行します。
`css/themes.css` と `js/palettes.js` の両方を生成し直し、各配色の墨色がその紙色に対して
7:1 のコントラストを、各カテゴリ色が 3:1 の非文字下限を満たすようにします。

```sh
python3 tools/gen_palettes.py    # tools/out/ に出力、css/ と js/ に上書き
```

カテゴリ色は塗りと罫線にしか使われず、文字には決して使いません。予定のブロックは
カテゴリ色のごく淡い地に、左端の一本の実線、そして墨色の文字です。25 配色すべてが——
派手なものも含めて——読めるままなのはそのおかげです。どの図表も色に文字ラベルを添えるのも
同じ理由です。

## ファイル構成

```
index.html        アプリ本体
gadget.html       デスクトップガジェット
css/
  themes.css      25 配色 —— それぞれ七つの生トークン
  app.css         デザインシステム、色はすべて導出
  gadget.css      パネル、同じトークンの上に
js/
  palettes.js     選択画面用の配色メタデータ
  i18n.js         8 言語、プリセット名、日付と時間の書式
  fonts.js        文字体系ごとの書体プラン
  util.js         日付、時間、DOM ヘルパ
  store.js        データモデル、localStorage、集計
  theme.js        配色のプレビュー / 適用 / 保存
  calendar.js     時間割 + 月グリッド、ドラッグ操作
  heatmap.js      年間グリッド、連続日数、リズムのパネル
  stats.js        タイル、推移、カテゴリ/項目/活動の棒、表
  categories.js   カテゴリ・項目・活動
  gadget.js       デスクトップパネル
  app.js          ルーティング、トップバー、記録エディタ、設定
macos/
  Sources/        Swift：アプリデリゲート、Web ホスト、ガジェットパネル、データファイル
  build.sh        swiftc + 手組みのバンドル -> Study Ledger.app
  make-icon.py    画像ライブラリなしでアイコンを描く
tools/
  gen_palettes.py themes.css と palettes.js を生成し直す
```

素のスクリプトを順番に読み込むだけ——モジュールを使っていないので `file://` でも動きます。

macOS アプリは同じウェブアプリを `WKWebView` に入れ、バンドル内部から `ledger://` スキームで
配信したものです。唯一違うのは保存先で、ブラウザでは `js/store.js` が `localStorage` を
使い、アプリでは `window.LedgerNative` と話して Swift が JSON ファイルを持ちます。これが
あるから、ガジェットもメニューバーもメインウィンドウも同じ数字を読めるのです。

表示言語、書体プラン、週の始まり、グリッドが開く時間帯、ドラッグの刻み（5/10/15/30 分）、

## 以前のエクスポートからの移行

項目という階層ができる前のエクスポート（`"v": 1`）も問題なく読み込めます。実際に記録を
持っているカテゴリには、そのカテゴリと同じ名前の項目が一つでき、記録はその下に収まります。
記録した時間が失われたり迷子になったりすることはなく、もともと空だったカテゴリに
穴埋めの項目がつくられることもありません。そのあとは、その項目の名前を変えるなり分割
するなり、ご自由に。
