# 學習帳簿 · Study Ledger

[English](README.md) · [简体中文](README.zh-Hans.md) · **繁體中文** · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

一個用來弄清學習時間究竟花在哪裡的行事曆——可以在時間表上劃出時段，有 GitHub 風格的
年度熱力圖，還有按日、週、月、年或學期統計的時間消耗報告。

兩種執行方式：作為帶桌面小工具和選單列讀數的 **原生 macOS 應用程式**，或者作為完全
不需要建置步驟的普通網頁。八種介面語言、二十五套配色，以及為每種文字各備的字體方案。

---

## 執行

### macOS 應用程式

```sh
./macos/build.sh --run
```

這會把通用架構的 `Study Ledger.app` 編譯到 `macos/build/` 並開啟它——約 900 KB，
不需要套件管理器，也沒有 Xcode 專案檔。唯一的要求是 Xcode 或命令列工具附帶的 Swift
工具鏈。把應用程式拖進 `/Applications` 即可長駐。

```sh
./macos/build.sh            # 僅編譯
./macos/build.sh --test     # 編譯後執行無介面自我測試
```

應用程式採用臨時簽章（ad-hoc），本機執行已足夠。若要分發給別人，請把 `macos/build.sh`
裡的 `codesign` 那一行換成 Developer ID 憑證並進行公證。

資料保存在 `~/Library/Application Support/Study Ledger/ledger.json`——一個可以備份、
同步或直接編輯的普通檔案。應用程式選單中有 **在 Finder 中顯示資料檔**。

### 在瀏覽器中

按兩下 `index.html`，或者把整個資料夾跑起來：

```sh
python3 -m http.server 8000
# 然後開啟 http://localhost:8000
```

用本機伺服器較為穩妥：瀏覽器在 `file://` 下會依檔案劃分 `localStorage` 的作用域，因此
以伺服方式開啟可確保即使移動了目錄，紀錄仍在同一處。

在瀏覽器中，所有內容都存在鍵 `study-ledger-v1` 底下。無論哪種方式都不需要帳號，也不會
有任何資料離開本機。**設定 → 匯出 JSON** 可寫出備份，**匯入 JSON** 可還原，因此你可以
在應用程式與瀏覽器之間來回搬移。

## 資料模型

三個層級，而行事曆是它們共同的輸入方式：

```
課程作業                              ← 分類：工作的種類
  ├ 高等最佳化                        ← 項目：具體的課程、專案或書
  │   聽課 · 做筆記 · ⋯               ← 活動：你做了什麼
  └ 數值方法
研究專案
  ├ 醫學影像分割
  └ 機器學習市場預測
閱讀 · 技能與語言 · 其他
```

- **分類** —— 工作的種類。預置了 *課程作業*、*研究專案*、*閱讀*、*技能與語言* 和
  *其他*。在 **分類** 檢視中只有分類出現在最上層；點擊其中一個即可展開它底下的項目。
- **項目** —— 你實際投入時間的對象：一門課、一個專案、一本書。項目位於分類 *之內*，
  絕不與分類並列，並且是每個行事曆色塊的標題——因為「高等最佳化」一眼看去比「聽課」
  說明得更多。一個項目只屬於一個分類，並且隨身帶著它：在編輯器中選定項目，也就替你
  回答了分類。
- **活動** —— 時間是怎麼花掉的。活動屬於 *分類*，因此課程作業底下的每門課共用同一套
  詞彙——聽課、做筆記、作業 / 習題、線上課程、教科書閱讀、實驗 / 實作、輔導 / 答疑、
  複習、備考、小組專案——而不必在每個項目底下重複一遍。
- **紀錄** —— 行事曆上的一個色塊：一個分類、一個項目、一個活動。它的長度 *就是* 消耗
  的時間，所以應用程式中的每個合計都不過是色塊之和。

三者都可以在 **分類** 中編輯：就地更名、換色、新增、刪除。在編輯器裡選擇
**+ 新增項目……** 或 **自訂……**，新名稱會被併入該分類的清單，下次一點即到。更名會
連同已記錄的時間一起帶走；刪除項目會同時刪除歸在它名下的時間，並會事先說明。沒有項目
的分類不會顯示任何項目清單——不會憑空造一個來填空。

### 新增一筆紀錄

編輯器 **先問項目**，把你所有的項目按分類分組列出。選中一個，分類就會被填好並鎖定，
於是剩下要選的只有活動。鎖是要刻意打開的——點一下那把小鎖——之後更改分類會把該項目
重新歸檔，並把它全部的歷史紀錄一起帶過去。全新的項目會讓分類保持解鎖，因為它總得歸到
某處。

一筆紀錄以「日期 + 距零點的起訖分鐘數」保存，而不是 UTC 時間戳記——所以時鐘變動時，
一段學習不會漂到錯誤的日子上。跨過午夜的時段會在 00:00 拆分為兩筆紀錄保存。

## 各個檢視

**行事曆** —— 日、週、月三種。在日網格上：在空白處拖曳即可劃出一段，單擊則預設為一小時；
拖曳色塊可移動（也可橫向跨天），拖曳底邊可改變時長，點擊則進入編輯。小時範圍以你的
設定為準，但總會自動向外延伸以容納實際紀錄，因此不會有內容被裁掉。

**熱力圖** —— 一年中每天一格，用配色主色的五級色階呈現，附帶連續天數、依分類篩選、
逐月合計和各星期平均。達到最深一階所需的單日總時長是一項設定，而不是對你資料的猜測。

**統計** —— 頂部數字卡片、每日/每週/每月小時數（分組粒度隨範圍自動調整），然後是
**依分類**、**依項目** 和 **依活動** 的時間，以及一張三層深的表格。仍在進行中的時段，
會依已經過去的天數來平均和比較，因此每月一號不會讀成「−99%」。

**分類** —— 上文的層級結構，每個分類、項目和活動都帶有累計時長。

**配色** —— 25 套方案。停留即可預覽整個應用程式，點擊則確認。

## 桌面小工具

一個無邊框面板，顯示今天相對目標的進度、本週、今天的時間具體去了哪裡，以及最近十週的
形狀。用 **⌘G**、**顯示方式** 選單或選單列圖示可以開關它。

它可以處於兩種層級之一，用它角上的箭頭或 **顯示方式** 選單切換：

- **固定至桌面** —— 與桌面圖示同層，位於所有一般視窗之後。這是經典的小工具形態：
  清空螢幕時它就在那裡，工作時又絕不礙事。它還會略微變淡，讀起來像是背景的一部分。
- **置於最前** —— 在一切之上，適合需要盯著數字的時候。

可以隨意拖曳；它會記住你放下它的位置，並跟著你在各個「桌面」之間移動。可在限度內縮放。
它會隨目前的配色與字體方案變化，並在主視窗有任何儲存動作時立刻重新整理。

**選單列圖示** 在一個小書本符號旁顯示今天的合計，使用應用程式自己的語言和時長格式——
`2h 30m`、`2小時30分`、`2 Std. 30 Min.`。它的選單可以開啟視窗、新增紀錄或開關小工具。
關閉主視窗後，小工具和選單列仍會繼續執行。

## 語言

English · 简体中文 · 繁體中文 · 日本語 · Español · Deutsch · Français · Latina

在 **設定 → 介面語言** 中選擇。首次執行時，如果瀏覽器自身的偏好語言在其中就採用它，
否則用英文。

改變語言只改變介面。你的分類、項目和活動名稱是你的資料，永遠不會被改寫——但是 *預設*
是在帳簿第一次執行時以當時的語言寫入的，因此從日文開始會得到「講義」和「課題」，而不是
Lecture 和 Homework。**還原預設** 會把目前語言的預設補進你已有的內容裡。

日期、星期與月份名稱、時鐘格式（英文用 12 小時制，其餘用 24 小時制）、時段標題和時長
一律隨語言變化——中文是 `7月2日` 和 `2小時15分`，德文是 `2. Juli` 和 `2 Std. 15 Min.`。
月份與星期名稱來自 `Intl`；`Intl` 未收錄的拉丁文，則在 `js/i18n.js` 中有一份手寫對照表。

要新增一種語言：在 `LOCALES` 中加一項、在 `S` 裡與其它語言並列加一張字串表，並在
`FORMATS` 中加一條時長格式——都在 [js/i18n.js](js/i18n.js) 裡。缺少的鍵會回退到英文，
而不是顯示原始的鍵名。

## 字體

一種語言需要的不只是把詞句譯過來，因此每種文字在 **設定 → 字體** 中都有自己的一組字體
方案。每套方案都帶有即時樣張，並註明它取法於什麼傳統；選擇是 *依語言分別記憶* 的，因此
日文可以用明朝體，同時英文用 Garamond。

| 文字 | 方案 |
|---|---|
| 拉丁 | **Ledger**（Fraunces / Spectral——目前偏 Tufte 風格的預設）· **Didone**（Playfair Display / Lora，取法 Bodoni 與 Didot）· **Renaissance**（EB Garamond，取法 Claude Garamont 1540 年代的羅馬體）· **Grotesque**（Bricolage Grotesque / Work Sans，Akzidenz 一脈） |
| 简体中文 / 繁體中文 | **宋體**（Noto Serif SC/TC——宋代刻本傳統）· **楷體**（LXGW 文楷 / 系統楷體——行筆的正書）· **黑體**（Noto Sans SC/TC）· **書法**（馬善政標題配宋體內文） |
| 日本語 | **明朝体**（Shippori Mincho）· **ゴシック体**（Zen Kaku Gothic New）· **丸ゴシック体**（Zen Maru Gothic）· **筆書体**（Yuji Syuku 標題配明朝內文） |

每套方案都刻意把一款拉丁字體與一款中日字體相配，並且字體堆疊的次序保證拉丁字形永遠取自
拉丁字體——所以「Advanced Optimisation」與「高等最佳化」同處一行時仍是同一種語氣。
只有方案真正用到的字體才會被下載：選定一套只會改寫一個 `<link>`。

要新增一套方案，在 [js/fonts.js](js/fonts.js) 對應的陣列裡加一項，寫明它的 `families`
（Google Fonts 查詢片段）以及 `display` / `body` / `mono` 三個字體堆疊。

## 配色

來自 Thomas Shang 的 Tufte 風格書籍範本的 24 套配色，加上原本的暖色預設方案，
移植自 [26-Xi-quizbank](https://github.com/Hatsuyuki017/26-Xi-quizbank)。

切換配色只是給 `<html>` 設定一個 `data-theme` 屬性。每套配色只宣告七個原始變數：

```css
[data-theme="kyoto"] {
  --p-bg:  #EAE2D4;   /* 紙色 */
  --p-ink: #222842;   /* 文字 */
  --p-a … --p-e;      /* 五種分類色 */
}
```

其餘所有顏色——各種底色、髮絲線、熱力圖色階、事件填充——都由這七個在 `css/app.css` 中
用 `color-mix()` 推導而來。別處沒有任何寫死的色值，所以配色不可能只套用一半。

要修改或新增配色，請編輯 `tools/gen_palettes.py` 中的 `RAW` 表並執行它；它會重新產生
`css/themes.css` 和 `js/palettes.js`，並保證每套配色的墨色在自己的紙色上達到 7:1 對比，
每個分類色達到 3:1 的非文字下限。

```sh
python3 tools/gen_palettes.py    # 輸出到 tools/out/，再覆蓋到 css/ 與 js/
```

分類色只用作填充和線條，從不用作文字：一個事件色塊是它分類色的淡淡一層底色，左側有一道
實色豎條，文字則用墨色。正是這一點讓全部 25 套方案——包括那些張揚的——都保持可讀。
每張圖表把顏色與文字標籤成對呈現，也是同一個道理。

## 檔案結構

```
index.html        應用程式本體
gadget.html       桌面小工具
css/
  themes.css      25 套配色 —— 每套七個原始變數
  app.css         設計系統，所有顏色皆由推導得來
  gadget.css      小工具面板，用同一套變數
js/
  palettes.js     供選擇器使用的配色中繼資料
  i18n.js         8 種語言、預設名稱、日期與時長格式
  fonts.js        依文字劃分的字體方案
  util.js         日期、時長、DOM 輔助
  store.js        資料模型、localStorage、彙總統計
  theme.js        配色的預覽 / 套用 / 保存
  calendar.js     時間表 + 月檢視，拖曳互動
  heatmap.js      年度網格、連續天數、節奏面板
  stats.js        數字卡片、趨勢、分類/項目/活動長條圖、表格
  categories.js   分類、項目與活動
  gadget.js       桌面面板
  app.js          路由、頂列、紀錄編輯器、設定
macos/
  Sources/        Swift：應用程式代理、Web 宿主、小工具面板、資料檔
  build.sh        swiftc + 手工組裝的 bundle -> Study Ledger.app
  make-icon.py    不依賴任何影像程式庫繪製圖示
tools/
  gen_palettes.py 重新產生 themes.css 與 palettes.js
```

普通腳本按順序載入——沒有模組，因此在 `file://` 下也能執行。

macOS 應用程式就是同一個網頁應用裝在 `WKWebView` 裡，透過 `ledger://` 協定從 bundle
內部提供。唯一不同的是儲存：在瀏覽器中 `js/store.js` 使用 `localStorage`；在應用程式中
它與 `window.LedgerNative` 通訊，由 Swift 掌管那個 JSON 檔。正是這一點讓小工具、選單列
和主視窗讀到同一組數字。

### 測試

```sh
./macos/build.sh --test     # 17 項原生檢查：橋接、寫入磁碟往返、小工具
```

網頁層由一套 jsdom 測試（131 項檢查——彙總計算、午夜拆分、項目/分類鎖、資料遷移、
全部八種語言）和一套 Playwright 測試（83 項檢查——真實的拖曳建立與拖曳移動、每種語言
下的每個檢視、430 px 寬度下無水平溢位）覆蓋。

## 設定

介面語言、字體方案、一週起始日、網格預設展開的小時範圍、拖曳吸附（5/10/15/30 分鐘）、
每日目標、熱力圖的飽和點，以及你的學期日期。學期是一份手工維護的清單；統計檢視的
**學期** 範圍從中讀取，‹ › 箭頭則在其中前後移動。

## 從更早的匯出升級

在項目層級出現之前所做的匯出（`"v": 1`）可以正常匯入。每個真正含有紀錄的分類會獲得一個
以該分類命名的項目，那些紀錄被歸入其下——沒有任何已記錄的時間會遺失或成為孤兒，而本來
就是空的分類也不會被塞進佔位項目。之後你可以隨意給這個項目更名或把它拆開。
