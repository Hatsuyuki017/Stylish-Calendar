# 学习账簿 · Study Ledger

[English](README.md) · **简体中文** · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [Français](README.fr.md) · [Deutsch](README.de.md)

一个用来弄清学习时间究竟花在哪里的日历——可以在时间表上划出时段，有 GitHub 风格的
年度热力图，还有按日、周、月、年或学期统计的时间消耗报告。

两种运行方式：作为带桌面小组件和菜单栏读数的 **原生 macOS 应用**，或者作为完全不需要
构建步骤的普通网页。八种界面语言、二十五套配色，以及为每种文字各备的字体方案。

---

## 运行

### macOS 应用

```sh
./macos/build.sh --run
```

这会把通用架构的 `Study Ledger.app` 编译到 `macos/build/` 并打开它——约 900 KB，
不需要包管理器，也没有 Xcode 工程文件。唯一的要求是 Xcode 或命令行工具自带的 Swift
工具链。把应用拖进 `/Applications` 即可长驻。

```sh
./macos/build.sh            # 仅编译
./macos/build.sh --test     # 编译后运行无界面自检
```

应用采用临时签名（ad-hoc），本机运行足够。若要分发给别人，请把 `macos/build.sh` 里的
`codesign` 一行换成 Developer ID 证书并进行公证。

数据保存在 `~/Library/Application Support/Study Ledger/ledger.json`——一个可以备份、
同步或直接编辑的普通文件。应用菜单里有 **在访达中显示数据文件**。

### 在浏览器中

双击 `index.html`，或者把整个文件夹跑起来：

```sh
python3 -m http.server 8000
# 然后打开 http://localhost:8000
```

用本地服务器更稳妥：浏览器在 `file://` 下会按文件划分 `localStorage` 的作用域，因此
以服务方式打开可以保证即使移动了目录，记录也仍在同一处。

在浏览器中，所有内容都存在键 `study-ledger-v1` 下。无论哪种方式都不需要账号，也不会有
任何数据离开本机。**设置 → 导出 JSON** 可写出备份，**导入 JSON** 可还原，因此你可以在
应用与浏览器之间来回迁移。

## 数据模型

三个层级，而日历是它们共同的录入方式：

```
课程作业                              ← 分类：工作的种类
  ├ 高等最优化                        ← 条目：具体的课程、项目或书
  │   听课 · 记笔记 · ⋯               ← 活动：你做了什么
  └ 数值方法
科研项目
  ├ 医学图像分割
  └ 机器学习市场预测
阅读 · 技能与语言 · 其他
```

- **分类** —— 工作的种类。预置了 *课程作业*、*科研项目*、*阅读*、*技能与语言* 和
  *其他*。在 **分类** 视图中只有分类出现在最上层；点击其中一个即可展开它下面的条目。
- **条目** —— 你实际投入时间的对象：一门课、一个项目、一本书。条目位于分类 *之内*，
  绝不与分类并列，并且是每个日历色块的标题——因为「高等最优化」一眼看去比「听课」
  说明得更多。一个条目只属于一个分类，并且随身带着它：在编辑器中选定条目，也就替你
  回答了分类。
- **活动** —— 时间是怎么花掉的。活动属于 *分类*，因此课程作业下的每门课共享同一套
  词汇——听课、记笔记、作业 / 习题、网课、教材阅读、实验 / 实践、辅导 / 答疑、复习、
  备考、小组项目——而不必在每个条目下重复一遍。
- **记录** —— 日历上的一个色块：一个分类、一个条目、一个活动。它的长度 *就是* 消耗的
  时间，所以应用中的每个合计都不过是色块之和。

三者都可以在 **分类** 中编辑：就地改名、换色、新增、删除。在编辑器里选择
**+ 新建条目……** 或 **自定义……**，新名称会被并入该分类的列表，下次一点即到。改名会
连同已记录的时间一起带走；删除条目会同时删除归在它名下的时间，并会事先说明。没有条目
的分类不会显示任何条目列表——不会凭空造一个来填空。

### 添加一条记录

编辑器 **先问条目**，把你所有的条目按分类分组列出。选中一个，分类就会被填好并锁定，
于是剩下要选的只有活动。锁是要刻意打开的——点一下那把小锁——之后更改分类会把该条目
重新归档，并把它全部的历史记录一起带过去。全新的条目会让分类保持解锁，因为它总得归到
某处。

一条记录以「日期 + 距零点的起止分钟数」保存，而不是 UTC 时间戳——所以时钟变动时，
一段学习不会漂到错误的日子上。跨过午夜的时段会在 00:00 拆分为两条记录保存。

## 各个视图

**日历** —— 日、周、月三种。在日网格上：在空白处拖动即可划出一段，单击则默认为一小时；
拖动色块可移动（也可横向跨天），拖动底边可改变时长，点击则进入编辑。小时范围以你的
设置为准，但总会自动向外扩展以容纳实际记录，因此不会有内容被裁掉。

**热力图** —— 一年中每天一格，用配色主色的五级色阶呈现，附带连续天数、按分类筛选、
逐月合计和各星期平均。达到最深一档所需的单日总时长是一项设置，而不是对你数据的猜测。

**统计** —— 顶部数字卡片、每日/每周/每月小时数（分组粒度随范围自动调整），然后是
**按分类**、**按条目** 和 **按活动** 的时间，以及一张三层深的表格。仍在进行中的时段，
会按已经过去的天数来平均和比较，因此每月一号不会读成「−99%」。

**分类** —— 上文的层级结构，每个分类、条目和活动都带有累计时长。

**配色** —— 25 套方案。悬停即可预览整个应用，点击则确认。

## 桌面小组件

一个无边框面板，显示今天相对目标的进度、本周、今天的时间具体去了哪里，以及最近十周的
形状。用 **⌘G**、**显示** 菜单或菜单栏图标可以开关它。

它可以处于两种层级之一，用它角上的箭头或 **显示** 菜单切换：

- **固定到桌面** —— 与桌面图标同层，位于所有普通窗口之后。这是经典的小组件形态：
  清空屏幕时它就在那里，工作时又绝不碍事。它还会略微变淡，读起来像是背景的一部分。
- **置于最前** —— 在一切之上，适合需要盯着数字的时候。

可以随意拖动；它会记住你放下它的位置，并跟着你在各个「桌面」之间移动。可在限度内缩放。
它会随当前的配色与字体方案变化，并在主窗口有任何保存动作时立刻刷新。

**菜单栏图标** 在一个小书本符号旁显示今天的合计，使用应用自己的语言和时长格式——
`2h 30m`、`2小时30分`、`2 Std. 30 Min.`。它的菜单可以打开窗口、新建记录或开关小组件。
关闭主窗口后，小组件和菜单栏仍会继续运行。

## 语言

English · 简体中文 · 繁體中文 · 日本語 · Español · Deutsch · Français · Latina

在 **设置 → 界面语言** 中选择。首次运行时，如果浏览器自身的偏好语言在其中就采用它，
否则用英文。

改变语言只改变界面。你的分类、条目和活动名称是你的数据，永远不会被改写——但是 *预设*
是在账簿第一次运行时以当时的语言写入的，因此从日语开始会得到「講義」和「課題」，而不是
Lecture 和 Homework。**恢复预设** 会把当前语言的预设补进你已有的内容里。

日期、星期与月份名称、时钟格式（英文用 12 小时制，其余用 24 小时制）、时段标题和时长
一律随语言变化——中文是 `7月2日` 和 `2小时15分`，德文是 `2. Juli` 和 `2 Std. 15 Min.`。
月份与星期名称来自 `Intl`；`Intl` 不收录的拉丁文，则在 `js/i18n.js` 中有一份手写对照表。

要新增一种语言：在 `LOCALES` 中加一项、在 `S` 里与其它语言并列加一张字符串表，并在
`FORMATS` 中加一条时长格式——都在 [js/i18n.js](js/i18n.js) 里。缺失的键会回退到英文，
而不是显示原始的键名。

## 字体

一种语言需要的不只是把词句译过来，因此每种文字在 **设置 → 字体** 中都有自己的一组字体
方案。每套方案都带有实时样张，并注明它取法于什么传统；选择是 *按语言分别记忆* 的，因此
日语可以用明朝体，同时英文用 Garamond。

| 文字 | 方案 |
|---|---|
| 拉丁 | **Ledger**（Fraunces / Spectral——当前偏 Tufte 风格的默认）· **Didone**（Playfair Display / Lora，取法 Bodoni 与 Didot）· **Renaissance**（EB Garamond，取法 Claude Garamont 1540 年代的罗马体）· **Grotesque**（Bricolage Grotesque / Work Sans，Akzidenz 一脉） |
| 简体中文 / 繁體中文 | **宋体**（Noto Serif SC/TC——宋代刻本传统）· **楷体**（LXGW 文楷 / 系统楷体——行笔的正书）· **黑体**（Noto Sans SC/TC）· **书法**（马善政标题配宋体正文） |
| 日本語 | **明朝体**（Shippori Mincho）· **ゴシック体**（Zen Kaku Gothic New）· **丸ゴシック体**（Zen Maru Gothic）· **筆書体**（Yuji Syuku 标题配明朝正文） |

每套方案都刻意把一款拉丁字体与一款中日字体相配，并且字体栈的次序保证拉丁字形永远取自
拉丁字体——所以「Advanced Optimisation」与「高等最优化」同处一行时仍是同一种腔调。
只有方案真正用到的字体才会被下载：选定一套只会改写一个 `<link>`。

要新增一套方案，在 [js/fonts.js](js/fonts.js) 对应的数组里加一项，写明它的 `families`
（Google Fonts 查询片段）以及 `display` / `body` / `mono` 三个字体栈。

## 配色

来自 Thomas Shang 的 Tufte 风格书籍模板的 24 套配色，加上原本的暖色默认方案，
移植自 [26-Xi-quizbank](https://github.com/Hatsuyuki017/26-Xi-quizbank)。

切换配色只是给 `<html>` 设置一个 `data-theme` 属性。每套配色只声明七个原始变量：

```css
[data-theme="kyoto"] {
  --p-bg:  #EAE2D4;   /* 纸色 */
  --p-ink: #222842;   /* 文字 */
  --p-a … --p-e;      /* 五种分类色 */
}
```

其余所有颜色——各种底色、发丝线、热力图色阶、事件填充——都由这七个在 `css/app.css` 中
用 `color-mix()` 推导而来。别处没有任何硬写死的色值，所以配色不可能只应用一半。

要修改或新增配色，请编辑 `tools/gen_palettes.py` 中的 `RAW` 表并运行它；它会重新生成
`css/themes.css` 和 `js/palettes.js`，并保证每套配色的墨色在自己的纸色上达到 7:1 对比度，
每个分类色达到 3:1 的非文本下限。

```sh
python3 tools/gen_palettes.py    # 输出到 tools/out/，再覆盖到 css/ 与 js/
```

分类色只用作填充和线条，从不用作文字：一个事件色块是它分类色的淡淡一层底色，左侧有一道
实色竖条，文字则用墨色。正是这一点让全部 25 套方案——包括那些张扬的——都保持可读。
每张图表把颜色与文字标签成对呈现，也是同一个道理。

### 阅读某套配色

每张卡片都带有一句提要和一个 **ⓘ**，点开即是这套配色自己的页面：完整的色条、一段关于
这些颜色从何而来的短文，以及一张列出全部七个色值的表格，附十六进制码和它们相对纸色的
对比度。表格的行以 *你自己的* 分类命名，因此页面告诉你的是「哪一种颜色属于课程作业」，
而不是「分类色 3」。

这些描述改写自
[Thomas Shang 的 Tufte 风格书籍模板](https://github.com/Hatsuyuki017/Thomas-Tufte-Style-Book-Template)
中的「色彩哲学」与「设计逻辑」，并以全部八种界面语言写成——共 200 条，见
[js/palette-notes.js](js/palette-notes.js)。某种语言若缺少某套配色的描述，会回退到英文，
因此新增配色严格来说只需要写英文一条。

### 自己做一套

**配色 → 自定义一套** 会打开同样这七个色值的编辑器：纸色、墨色，以及五种分类色，每一项
都配有取色器和十六进制输入框。你拖动的同时整个应用即时重绘，而每一行都会显示它相对纸色
的对比度，并对照生成器所用的下限——墨色 7:1，分类色 3:1——因此在保存之前就能看出某个
选择是否失当。你的配色排在内置配色之上，之后仍可编辑或删除，并会随 JSON 导出一起迁移。

由于一套配色同时决定纸色，**深色配色会给你一个深色的应用**。推导出的各种底色平常是从
纸色朝白色迈进；当纸色的亮度低于 0.15 时，它们改为朝相反方向迈进，于是面板是浮出背景
而非陷进去。25 套内置配色都是浅色的——最深的「静静的顿河」为 0.196——所以既有的一切
都不会改变。

## 文件结构

```
index.html        应用本体
gadget.html       桌面小组件
css/
  themes.css      25 套配色 —— 每套七个原始变量
  app.css         设计系统，所有颜色皆由推导得来
  gadget.css      小组件面板，用同一套变量
js/
  palettes.js     供选择器使用的配色元数据
  i18n.js         8 种语言、预设名称、日期与时长格式
  fonts.js        按文字划分的字体方案
  util.js         日期、时长、DOM 辅助
  store.js        数据模型、localStorage、聚合统计
  theme.js        配色的预览 / 应用 / 持久化
  calendar.js     时间表 + 月视图，拖动交互
  heatmap.js      年度网格、连续天数、节奏面板
  stats.js        数字卡片、趋势、分类/条目/活动条形图、表格
  categories.js   分类、条目与活动
  gadget.js       桌面面板
  app.js          路由、顶栏、记录编辑器、设置
macos/
  Sources/        Swift：应用代理、Web 宿主、小组件面板、数据文件
  build.sh        swiftc + 手工组装的 bundle -> Study Ledger.app
  make-icon.py    不依赖任何图像库绘制图标
tools/
  gen_palettes.py 重新生成 themes.css 与 palettes.js
```

普通脚本按顺序加载——没有模块，因此在 `file://` 下也能运行。

macOS 应用就是同一个网页应用装在 `WKWebView` 里，通过 `ledger://` 协议从 bundle 内部
提供。唯一不同的是存储：在浏览器中 `js/store.js` 使用 `localStorage`；在应用中它与
`window.LedgerNative` 通信，由 Swift 掌管那个 JSON 文件。正是这一点让小组件、菜单栏和
主窗口读到同一组数字。

## 从更早的导出升级

在条目层级出现之前做的导出（`"v": 1`）可以正常导入。每个真正含有记录的分类会获得一个
以该分类命名的条目，那些记录被归入其下——没有任何已记录的时间会丢失或成为孤儿，而本来
就是空的分类也不会被塞进占位条目。之后你可以随意给这个条目改名或把它拆开。
